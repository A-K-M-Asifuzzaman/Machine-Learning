## Build order

Chapters are built in dependency order, not table order, so that every chapter can rely on
everything before it:

1. **Foundations first** (Part 0) — every later derivation cites these.
2. **Toolkit** (Part 1) — so code in later chapters needs no digression.
3. **Data → Supervised → Evaluation** (Parts 2, 3, 5) — the practical core.
4. **Unsupervised → Ensembles** (Parts 4, 6) — completes classical ML.
5. **Deep learning** (Part 7) — then the domain parts branch from it.
6. **Domains** (Parts 8-16) — in whatever order is most useful.
7. **Responsible ML, production, research** (Parts 17-21).
8. **Applied** — interview prep and projects, drawing on everything above.

## Definition of done

A chapter is 🟢 only when all of the following hold:

- [ ] `README.md` contains: intuition, the objective function, a **complete** derivation
      (no "it can be shown that"), stated assumptions, computational complexity,
      failure modes, and practical guidance
- [ ] `from_scratch.py` runs standalone and prints a numerical comparison against the
      reference library implementation
- [ ] `notebook.ipynb` applies the method to real data with diagnostic plots
- [ ] `exercises.md` has derivation, implementation, and interview-style questions
- [ ] `references.md` cites exact book sections and papers
- [ ] Every claim is either derived, cited, or empirically demonstrated in the notebook
